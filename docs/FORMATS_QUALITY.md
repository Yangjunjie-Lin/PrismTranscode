# 格式矩阵与保真说明

## 输出预设总表

“格式”分三层：扩展名、容器、内部编码。MP4 可以装 H.264/HEVC/AV1；M4A 可以装 AAC 或 ALAC。因此本项目让用户选择有明确内部编码的预设，而不只是替换文件名后缀。自动识别使用 FFprobe；强制输入只在已经知道容器而自动识别失败时使用，错误指定会报错。

| 分组 | 预设 ID | 文件 / 内部编码 | 主要限制 |
| --- | --- | --- | --- |
| 音频 | mp3 | .mp3 / LAME MP3 | 有损；默认高质量 320 kbps；兼容同编码音频可直拷 |
| 音频 | m4a / aac | .m4a / AAC；.aac / ADTS AAC | 有损；容器能力不同 |
| 音频 | flac | .flac / FLAC | 整数最高 24-bit；更高精度或浮点转换需量化，明确提示 |
| 音频 | wav / aiff | PCM WAV / AIFF | 按原输入选择整数或浮点 PCM；用户指定降低位深会改变样本 |
| 音频 | alac | .m4a / ALAC | 整数最高 24-bit；不是 AAC |
| 音频 | ogg / opus | OGG Vorbis / Opus | 有损；Opus 采用编码器支持的采样率 |
| 音频 | wma / ac3 | WMA v2 / AC-3 | 兼容预设；编码器对声道和采样率有限制 |
| 音频 | wv | .wv / WavPack | 无损编码器；实际样本表示受编码器支持范围影响 |
| 音频 | copy_audio | 按音轨编码决定扩展名 | 13 个音频预设中的原码提取项；不强制转成 MP3 |
| 视频 | mp4 / mp4_hevc / mp4_av1 | H.264 / HEVC / AV1 + AAC | 有损；默认软件编码；AV1 需要 libsvtav1 |
| 视频 | mkv | MKV / H.264 + AAC | 普通转码，非全轨复制 |
| 视频 | webm / webm_av1 | VP9 / AV1 + Opus | 输出 WebM；有损 |
| 视频 | mov_prores | ProRes 422 HQ + PCM | 中间编辑格式，非数学无损；大文件；本预设不保留 Alpha |
| 视频 | mkv_ffv1 | FFV1 + PCM | 解码画面归档，不改变帧率/尺寸；全轨元数据仍不保证完整 |
| 视频 | avi / mpeg / ts | MPEG-4/MP3；MPEG-2/MP2；H.264/AAC | 老设备兼容预设，不等于最佳压缩率 |
| 视频 | remux_mp4 / remux_mkv | 压缩流复制 | 共 13 个视频预设；源编码须与目标容器兼容 |
| 图片 | png / tiff / bmp | 静态图片 | 不重新引入有损压缩；元数据、位深/像素格式支持仍需检查 |
| 图片 | jpg / webp / avif | 静态图片 | 有损；JPEG 与本 AVIF 预设不保留透明通道 |
| 图片 | webp_lossless / jxl | 无损 WebP / 无损 JPEG XL | 静态；需 libwebp / libjxl；不能承诺所有位深均原样保留 |
| 图片 | gif | 动态 GIF | 共 9 个图片/动图预设；最多 256 色；默认 15 fps、最大 960 像素宽 |
| 字幕 | srt / vtt / ass | 文本字幕 | 共 3 个字幕预设；图像字幕不可直接变文本，复杂样式可能丢失 |

以上 38 个输出预设均使用合成样例执行过真实转换。此结论不能外推为“任何输入组合均通过”。例如同是 MP4，可能无音轨、包含不支持编码、DRM 或损坏数据。真正可用能力按运行时引擎检测，不按页面文案猜测。

## 输入范围

文件夹扫描收录常见音频：NCM、MP3、FLAC、WAV、M4A、AAC、AIFF、OGG、Opus、WMA、APE、WavPack、AMR、AC-3/E-AC-3、DTS、CAF、MKA、MP2；视频：MP4、MKV、MOV、WebM、AVI、FLV、WMV、TS/MTS/M2TS、MPEG/VOB、3GP、MXF 等；图片：PNG、JPG、WebP、AVIF、JXL、TIFF、BMP、GIF、APNG 以及部分引擎可读图片；字幕 SRT/VTT/ASS/SSA。目录过滤只是候选收录，不代表每种实际编码已经验证。

手动添加的普通文件不被扩展名白名单挡住，依靠实际内容探测。测试中把 MP4 更名为 `.data` 后仍正确识别为视频。NCM 使用真实签名识别，手动强制 NCM 也必须通过签名检查。支持本工具原有常见 NCM 封装，不声称覆盖未知后续变体。

## 怎样理解“精度高”

**第一优先级：减少不必要的变换。** 同编码音频且没有裁剪、采样率、位深、声道或显式码率修改时优先直拷。MP4/MKV 重封装复制媒体压缩包；文件整体哈希可能改变，因为容器索引和元数据重新写入。

**第二优先级：需要保留解码样本时使用无损存储。** 测试验证 24-bit WAV→FLAC 的解码 PCM 一致，RGBA PNG→PNG/无损 WebP/TIFF 的解码像素一致。它们是这些样例的确切结果，不是对所有颜色空间、位深和标签的绝对承诺。MP3→FLAC 不会恢复 MP3 丢失的细节。把 16-bit 提升为 24-bit 也不会凭空增加录音信息。

**第三优先级：必要转码才选择质量与体积。** 默认 high；H.264、HEVC、AV1、VP9 各有与编码器匹配的质量参数，不把不同编码器的 CRF 数字当作等价质量。软件编码为默认；硬件选项主要提供速度路径，不能保证同码率下更好的画质。参数详见实际 `internal/media/plan.go` 和任务执行记录。

采样率变化且引擎带 SoXR 时，采用 `aresample=resampler=soxr:precision=28`；28 指计算精度设置，不是输出文件具有 28-bit 位深。引擎没有 SoXR 时使用已声明的 SWR 回退，不谎报 SoXR。降低整数 PCM 位深时使用抖动策略；重新采样、声道混合、浮点转整数本身可能改变样本。

## 色彩、HDR、透明度与元数据

检测到 PQ/HLG 时，普通有损视频或图片转换会明确拒绝。可以选择兼容的原码重封装或 FFV1 归档；后者仍不保证动态 HDR/杜比视界辅助信息完整保留。本版没有自动色调映射流程，避免悄悄把 HDR 转成错误色彩的 SDR。

普通转码可能发生色彩空间、色度采样和像素格式转换。视频尺寸默认不主动放大；用户设置缩小上限或帧率时是有意变换。FFV1 档位不允许主动修改这些归档关键参数。

图片预设主要处理像素，不是完整 ICC/EXIF/XMP 色彩管理与专业印刷系统。透明图优先 PNG 或无损 WebP；JPEG 和本版 AVIF 不保留 Alpha。高位深图片转入 WebP 等可能降精度，正式素材先用小样比对。动画 GIF 转其他静态图片只取一帧；不要把单帧输出当作完整动图转换。

保留通用标题、歌手、专辑标签；不保证私有元数据、所有章节/字幕/封面/附件迁移。NCM 封面当前不导出。需要保留多轨内容优先兼容的原码重封装，随后用详情核对媒体流。

## 校验能证明什么

每次成功输出都会再次 FFprobe 探测流结构和时长。默认还完整解码所有输出音视频流，失败不提交成品。TIFF 使用完整像素解码加 CRC/位流/缓冲区检查，避免 FFmpeg 7.x 的 explode 模式把合法但不支持的附属标签误认为像素错误。文本字幕“已验证”仅表示重新解析，不表示样式一致或语言准确。

SHA-256 用于检验输出文件后来是否改变，不是原始质量评分，也不等于有损转码前后的画质相同。自动校验不替代人工视听检查；当前没有对真实内容实施 VMAF/SSIM/PESQ 等质量基准，也不报告虚构的“99.9% 精度”。

# 工程架构

## 处理管线

本地路径/本机导入缓存 → 格式适配（NCM 可选解码）→ FFprobe 实际探测 → 验证参数并生成命令计划 → FFmpeg 执行 → 重新探测与完整解码检查 → SHA-256 → 不覆盖式提交 → 任务收据。

识别层、计划层和执行层分离。预览与正式执行使用同一个 `media.Build`，不另写一套可能偏离实际输出的说明逻辑。每个任务保存自身 Options，不依赖运行时全局下拉框值。

## 模块边界

| 模块 | 输入 | 输出与责任 |
| --- | --- | --- |
| `ncm` | 只读原始 NCM | 严格长度/签名检查、流式提取、文字元数据；不把未知变体当成功 |
| `media.Prepare / Probe` | 原路径、选定引擎、输入解释方式 | 临时媒体路径和 Info；Info 包含真实流、容器、HDR、标签与警告 |
| `media.Build` | Engine、Info、Options | Plan：参数数组、目标容器/扩展名、原码/转码方式、明确警告 |
| `media.Execute` | Plan 所需输入及输出目录 | Result：实际参数、日志、输出结构、校验方式、哈希、耗时 |
| `jobs.Manager` | 任务列表和启动/停止请求 | 1–4 工作者、单任务失败隔离、进度与队列快照、恢复状态 |
| `installer` | 用户明确选择发行渠道 | 验证过的独立引擎目录、来源/哈希/时间收据；不自动执行下载脚本 |
| `main / web` | 本机浏览器请求 | 单用户工作台；所有 API 鉴权；UI 不上传外网 |

## 队列与输出规则

任务状态：`ready → waiting → running → completed / failed / cancelled / skipped`。重新配置已完成任务会清空旧任务结果指针并回到 ready，但不会删除已经生成的文件。日志导出应在重新配置前保存。

JSON 快照用临时文件写入并替换；恢复时把 running/waiting 标记为 cancelled，不伪造“续传进度”。重试从头处理。默认目录最多 5000 个队列任务，媒体数据流式处理，不一次载入全部文件。

输出先写 `.prism-output-*` 临时文件，成功校验才进行排他提交。优先硬链接提交以避免覆盖竞态；不支持硬链接的文件系统使用排他创建复制，仍不覆盖已有文件，但不声称跨文件系统绝对原子。正常停止会清理本任务临时文件；断电/强杀可能留下临时内容，可退出程序后按命名识别再人工清理。

当前没有跨进程单实例锁和数据库事务。不要并行启动多个实例使用同一 data-dir。未来多用户服务需单独实现隔离账户、任务数据库、队列调度、沙箱、配额及认证，而不是把本机接口直接暴露公网。

## 扩展一种输出格式

在 `internal/media/plan.go` 增加 Target，明确扩展名、容器、编码器和有损范围；在 Build/audioEncode/videoEncode 中添加经过校验的参数，不接受前端任意命令字符串。更新输入输出兼容判断、能力检测与警告，并为可解码、无流、损坏文件、同名保护、取消、输出核验添加测试。更新格式矩阵及前端提示。

扩展新的受控输入容器，应新增独立适配器而不是混入 FFmpeg 命令层；未知版本必须 fail closed。不要因为扩展名相近就假定已支持。

## 运行数据目录

Windows 默认 `%APPDATA%\PrismTranscode`；可用 `--data-dir` 改到独立目录。

```text
settings.json             选定引擎与输出目录
queue.json                本地任务、路径、执行记录
imports/                  浏览器拖放导入副本，需自行管理磁盘空间
session-*/                本次 NCM 解码临时数据，正常退出清理
engines/<hash-prefix>/    下载并核验的独立引擎版本
  engine-receipt.json     下载来源、压缩包 SHA-256、安装时间
application.log           应用错误日志
last-session-url.txt      本次地址（含敏感会话令牌，不应分享）
```

浏览器本地存储保存右侧临时参数；由于随机端口造成不同 origin，不把它当作跨启动的可靠设置数据库。需要长期复用参数，应导出 JSON 预设。各已导入任务的参数会随队列保存。

## 可重复与可维护

自有源码使用 Go 标准库，不需要第三方 Go modules；前端无 npm、CDN、遥测和远端字体。安装的引擎版本与构建选项决定实际编解码能力，任务记录保留版本与实际命令。

字节级可重复要求固定源码、Go 工具链、编译选项；媒体输出的重复性还受引擎、编码器、平台、硬件、线程和元数据影响。不能因为主程序构建可重复就承诺所有编码结果逐字节一致。
